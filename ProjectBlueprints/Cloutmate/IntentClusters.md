# Intent Cluster Prediction (Phase 5++)

Aurora analyzes recent conversations to predict what the user is likely to focus on next. This predictive context appears in the payload under "Intent Clusters" and informs both model routing and conversation openings.

---

## 1. Source Data

- `ConversationDigest` records (summaries, topics, emotional tones) generated by `ConversationArchive.digestConversation()`.
- Up to 10 most recent digests (excluding the current conversation) feed the clustering pipeline.
- Exponential decay (λ = 0.65) weights recency to avoid overemphasizing stale threads.

---

## 2. Algorithm (`ConversationArchive.extractIntentClusters`)

1. Fetch recent digests and sort by recency weight.
2. Build labeled conversation snippets containing title, summary, topics, tone, and weight metadata.
3. Prompt `CoreResponseService` with a JSON-only instruction describing canonical clusters:
   - Empathy/Support
   - Orchestration/Planning
   - Creative/Brainstorming
   - Execution/Action
   - Reflection/Learning
4. The AI response must include:
   ```json
   {
     "clusters": [
       {"name": "Creative/Brainstorming", "topics": ["..."], "conversationCount": 3, "dominantEmotions": ["..."], "description": "...", "dominance": 0.65},
       ...
     ],
     "primaryCluster": "...",
     "secondaryCluster": "...",
     "clusterDominanceScore": 0.8,
     "isTied": false,
     "disambiguatingQuestions": ["..."]
   }
   ```
5. Parse the JSON, fallback to manual parsing if needed, and derive:
   - `confidence` = min(1, dominance score × history length × recency score)
   - `tieBreaker` = CPS top item or recent action verb if dominance < 0.55
   - `shouldAbstain` when confidence < 0.4 (Aurora must present two likely paths + ask clarifying question)

---

## 3. Downstream Usage

- **Payload Context** – `AIPayloadContext.intentClusters` surfaces cluster summaries so Aurora can respond to "What will I focus on next?" questions.
- **Model Routing** – `ModelRoutingEngine` caches the last-used model per cluster (cluster stickiness), improving continuity.
- **Predictive Context** – `PredictiveContextManager` correlates clusters with drift/fatigue to build `ClusterRiskProfile`s.
- **Insights UI** – Intent clusters appear in the AI panel when Aurora proactively surfaces predictions.

---

## 4. Extensibility

- Adjust cluster taxonomy inside `ConversationArchive.extractIntentClusters` prompt if new intent modes emerge.
- Modify decay lambda or history size to tune sensitivity.
- Consider caching parsed results in SwiftData for analytics; currently the summary is transient.

---

## 5. Testing & Validation

- Use `/ProjectBlueprints/FocusOS/CommandSystem.md` to trigger conversation activity, then call Aurora: "Based on our recent conversations, what do you think I'm about to focus on?" Ensure she references the predicted clusters and confidence.
- Check logs (`os_log` category `ConversationArchive`) for JSON parsing failures.
- Add unit tests in `FocusOSTests` to mock digests and verify confidence/abstention logic.

Intent clusters are the bridge between conversation history and predictive posture—keep them well-fed with digested conversations to maintain accuracy.
